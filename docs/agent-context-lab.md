# 上下文与检索实验：保存过，不等于本轮看得见

本实验对应[学习路线](agent-learning.md)第2单元。通过六组受控输入，观察检索来源、历史裁剪和任务ID的可见性；每一项判断来自本次模型HTTP请求与持久记录，不依赖模型对自己的描述。

运行的是当前Node实现、真实AgentScope 2.0.8 / prefork和独立临时SQLite；模型回复由本机fixture预设。实验不评价真实回答质量，不引入向量检索或长期记忆。

## 运行与报告

在仓库根目录完成[SDK安装](agentscope-runtime.md)后运行：

```sh
npm run agent:check
npm run agent:learn:context
```

报告写入 `test-results/learning/context-lab.md` 和 `context-lab.json`，包括每组预期与实际、模型输入的结构观测、来源覆盖、字节数、台账、时间及固定源码清单摘要。再次执行会更新文件，要比较两次结果应先保留副本。实际交付结果见[验证记录](verification.md)，下表只列实验预期。

命令不接受额外参数或 `--real`，不加载 `.env`、真实模型配置或正常业务数据库。每组只向模型提供本机 `service_status` 只读工具的schema；受控模型直接回答，因此六组都应没有实际工具调用或持久工具步骤。准备阶段的本地MCP连接/目录发现不算工具调用。正常结束或场景初始化成功后捕获异常时会清理本轮临时数据库、HTTP服务和Worker；初始化中断或进程被强制终止时，不保证清理完成。本次未做信号中断验收。

本地费用单价与每日费用限额均固定为0（`MODEL_PRICE_PER_MILLION` / `DAILY_COST_LIMIT`），避免继承宿主非零费用限额后在请求模型前误报503。此隔离只作用于实验进程，不修改业务部署的费用规则。

## 先预测，再运行

| 场景 | 只改变什么 | 预期观察 |
| --- | --- | --- |
| ranked | 检索模式为默认排序 | 高分长文占据前5个片段，来源仅1篇 |
| diverse | 相同资料改为多文档选择 | 覆盖3篇，每篇最多2段且不重叠；可能只有4段，不强凑5段 |
| recent历史 | 保留近30条的原模式 | 14轮历史加当前问题共29条候选；最早轮的合成任务ID仍在请求中 |
| budgeted历史 | 相同历史加8000字节预算 | 删除完整旧轮次；ID仍在数据库，却不再进入本次模型请求；system带省略提醒 |
| 当前补回ID | 相同预算，当前问题重新提供ID | 当前问题原样保留，ID重新可见 |
| 必需输入超限 | 当前问题本身超过预算 | 422，模型请求0、工具调用0，保存失败记录 |

前五组预期各有一次模型请求；最后一组预期被拒绝。模型每次固定返回30tokens，这只用于核对台账，不是实际分词或计费测量。最后一组的HTTP错误是预期门禁，报告应判该场景通过；只有实际不符合预期才应失败并以非零状态退出。

## 对照一：片段多，不等于来源多

三篇合成资料分别围绕计费延迟、网络和数据库，另设过期资料验证排除。长文的标题与正文重复命中查询词，默认排序可能让它占满五个名额；diverse先给各匹配文档一个位置，再补同文档的非重叠片段。

核对报告中的来源标识、偏移、片段长度与分数。不要把3篇资料解释为一定比1篇更准确：多样性增加覆盖，也减少某篇高分长文占有的上下文。本项目使用中文二元词项、FTS5候选与字符串评分，同义词或语义相近的资料仍可能漏检。

## 对照二：数据库、消息窗口和预算是三个边界

实验把合成任务ID放在最早一轮，只在当前问题要求“继续检查”。先核对数据库确实还保存ID，再看本次HTTP请求是否包含它。

后端先取最近30条user/assistant文本，再做可选预算裁剪。本实验用29条候选，专门隔离第二步的影响。更旧的消息可能在第一步就被排除；`omittedMessages`只统计已选窗口内被预算省略的消息，不统计数据库里全部未发送的历史。

budgeted按完整user轮次删除最早历史，不能把某个旧问题与其回答拆成不完整一对。system、已选知识、工具定义与当前问题不会通过这个算法被删除；必需部分本身过大时直接拒绝。

当旧ID从输入消失时，只能得出“本轮模型没有收到这条事实”。system的省略提醒要求缺信息时追问，但本机预设模型的回答不能证明真实模型一定遵守。再把ID放进当前问题，检查它重新可见，才是可重复的工程证据。

## 对照三：两种字节数不能混用

预算统计的上下文字节来自 `contextBytes(messages, tools)`，使用UTF-8 JSON序列化，包含中文和转义开销。模型HTTP请求体还含model、max_tokens、temperature等字段，结构也不同，因此报告的请求体字节不要求等于上下文字节。

比较recent与budgeted时，先说明采用哪一种口径，再根据本次实测计算变化。字节减少不等于tokens同比减少，更不等于真实账单同比减少；本实验也不测真实模型延迟或答案质量。

## 三分钟复盘

用30秒解释“数据库保存、窗口选择、预算裁剪”的区别；用60秒指出报告中ID在库但不在请求、重新提供后恢复的证据；用60秒解释ranked/diverse的覆盖取舍；最后用30秒说明字节与tokens、受控模型与真实质量的区别。

留下自己的运行时间、三个历史对照的ID可见性、两种检索模式的来源数、一个输入大小实测和一项未验证边界。没有亲自运行时可以说阅读了实验，不把自动报告写成自己的实测贡献。
