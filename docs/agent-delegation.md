# 自主委派：主 Agent 如何调用子 Agent

当问题包含多个可分开的只读分析任务时，在聊天输入区开启「允许委派」后发送。主 Agent 会获得内部 `delegate_agents` 工具，决定是否拆分、分给哪个 Agent，并在结果回传后汇总答复。开关只允许委派，不保证每条问题都会拆分；无需拆分时保持普通问答。默认关闭，生成期间不可切换。本轮选择加入执行输入和幂等摘要，新会话或刷新恢复默认关闭。

例如：“查询已确认的 billing 服务状态，并独立整理相关手册中的排查方法，最后说明证据与缺口。”主 Agent 可以把查询和资料分析分给不同子 Agent。实际是否委派由模型请求决定，不能把这个例子当作真实模型已验收的效果。

## 从请求到汇总

1. **主任务准备。** 身份、本人会话、已发布资源、检索和 MCP 目录先按原规则准备。开启委派后，主模型看到允许委派的工具和可见已发布子领域名单。
2. **模型提出委派。** 内部工具接受 `tasks` 数组，每项包含 `agentId` 与 `task`。`agentId=null` 使用通用子 Agent，指定 ID 使用该子领域已发布的职责配置。参数必须与 Node 保存的模型原始调用一致，Worker 不能改写它。
3. **创建独立子任务。** 子任务使用独立 AgentScope Worker、上下文和运行身份。它只得到主模型写出的子任务和获准资料，不继承整段会话历史，也不共享父 Worker 的 Agent 对象。
4. **收窄资源与执行。** 子任务取主任务可用资源与自身绑定资源的交集，只提供只读工具。子模型与工具仍经过 Node 的模型出口、脱敏、预算、权限、Schema、目标比较和持久步骤治理。
5. **回传实际结果。** 完成结果、失败状态、来源标识、步骤数量和用量组成有界结构化返回。它们属于待核实数据，不能授予权限；失败结果不能当作业务查询成功。
6. **主模型汇总。** 子任务返回后，主模型继续推理和组织答复。开启独立复核时，复核 Agent 再接收候选、实际子任务证据与来源，仍不拥有工具权限。最后保存消息与全景。

子 Worker 使用单独、有界的 cold 启动通道。即使主运行池只配置一个 prefork Worker，主 Agent 等待子任务也不会把子任务堵在自己占用的槽位后面。当前跨父执行同时运行的子 Worker 最多3个，排队同样受父执行超时与取消控制。

## 权限、范围与限制

| 项目 | 当前规则 |
| --- | --- |
| 委派深度 | 1；子 Agent 没有委派工具，不能继续派生 |
| 每批子任务 | 1–3，可并行处理 |
| 每轮子任务总数 | 最多4个，包含已失败的任务 |
| 子任务模型轮次 | 每个最多3轮模型/工具往返 |
| 主任务模型轮次 | 普通分析最多6轮；独立复核时分析最多5轮、复核最多1轮 |
| 全局模型轮次 | 主分析与全部子任务最多12轮，开启复核时预留1轮 |
| 网络恢复 | 单轮沿用现有最多6次尝试；恢复不增加工具往返轮次，但实际尝试计入用量 |
| token、费用与超时 | 与主执行共用，包含并发在途请求的预留，子任务没有独立额外额度 |
| 子任务输入/返回 | 任务最多6000字符；返回正文最多4000 UTF-8字节（保留完整Unicode字符），截断明确标记 |
| 子工具 | 只读、主子授权交集；不能扩大用户确认的工具、环境和目标值 |
| 停止与重启 | 停止父执行中止活动子任务；进程重启将遗留活动子任务标记中断，不重放 |

通用子 Agent 同样不能超出父任务范围。子领域名与专门指令不授予额外资源权限；资源被撤权、停用或修订后，下一次模型/工具处理及汇总前再次检查。读操作也必须符合用户已确认的目标绑定。首版不开放子任务写操作、自动审批、递归、跨用户协作或脱离主执行的长期后台任务。定时任务仍沿用当前默认关闭行为，没有新增定时委派配置。

## 在全景中理解数据经过的节点

打开消息下的「本轮全景」，查看主 Agent 与每个子 Agent 的分组。委派节点连接到子 Agent 分支，分支内显示实际授权上下文、选入的 Skill/知识、继承的只读目录、共享预算检查、模型请求和真实工具步骤；「返回子任务结果」连接到主任务的「汇总子任务结果」，再进入后续模型与答复。

点击节点查看身份、上游/下游、状态、实际耗时、消息/字符数量、来源与步骤计数，并可跳到所属父节点。节点列表适合窄屏，支持键盘与父子分组定位。失败、取消和预算拒绝保留实际状态；并行分支的耗时不能简单相加。导出 JSON、刷新后的消息和实时记录沿用相同节点与父子身份。

这里展示应用可观测的处理流程。不会展示模型私有思考、原始子任务提示、完整工具参数/返回正文或凭据；可见的输入输出概况、授权范围、计数和受控摘要用于理解数据处理，不构成全量回放，也不证明模型实际引用了某条资料。旧消息缺失的节点不会补造，旧版全景仍可阅读。达到200节点/400连线记录上限时明确提示省略数量，不能把部分图谱当作完整处理回放。

## 持久化与排查

数据库 schema v7 增加 `agent_delegations`，关联同一父 `executions` 和用户，保存状态、时间、模型/工具统计、节点身份以及加密的任务和结果。聊天消息的 `metadata.agentDelegation` 和执行详情提供受控子任务摘要；完整图谱仍在 `metadata.executionTrace`。子任务不是额外侧栏会话，不自动增加“最近对话”条目。

工具步骤仍在原父执行的 `tool_steps` 中，以子运行身份隔离调用标识，避免两个子 Agent 的同名工具调用冲突。只读工具返回错误时，真实失败步骤仍计入子任务统计，并保留加密原始错误回复供独立复核；写操作的unknown与不重放语义沿用原机制，不因加密失败证据而允许重放。执行请求重放只回读原结果，不再次创建子 Agent。删除聊天不会删除独立执行和委派证据；备份、恢复和密钥轮换包含新增加密字段。旧版本回退需要兼容 schema 的构建或相应备份，不能只改 `user_version`。

独立复核仍是发布门禁，不会撤销已发生的只读查询；子任务内容和最终答复是否高质量需另做真实模型与人工评审。
