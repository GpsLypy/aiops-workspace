这里迭代的是项目实现、教学材料和验证证据，不是自动训练模型。下表的“交付”指学习资源准备完成，不表示用户已经掌握。个人练习记录与真实贡献仍由用户确认。

## 每轮工作方式

1. 阅读根规则、源码地图、本台账及 [验证记录](verification.md)，核对当前改动，选取一个尚未完成的主题。
2. 先提出一个能复现的问题，找到负责函数和已有测试，再确定最小改进。原理 → 源码 → 实验 → 证据 → 面试解释应连成一条线。
3. 默认使用本地临时数据和受控模型/MCP。课程展示预期，验证记录只写实际执行的结果。真实质量、性能和生产边界不得由 fixture 外推。
4. 涉及界面遵循 frontend-design，较大模块先用 OpenSpec；技能不可用时沿用仓库已有格式并记录。代码行为变更完成后按 agent.md 做全量回归、构建、对应专项、文档及官网同步。
5. 更新本台账的状态、交付、证据与下一个明确任务。仅新的交付、重要失败或需要用户行动时通知；不重复创建日程，不用重复润色充当进展。

日常学习待办用尽时给出下一阶段建议，等待用户选择。全天授权窗口内继续依次检查缺陷、交互与既有计划的验证缺口，避免无意义重复修改。涉及外部真实模型/业务系统的验收应单独界定目标和证据，不让教学任务自行扩张为生产操作。
