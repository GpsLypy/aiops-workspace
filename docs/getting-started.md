# 从零启动与使用

本章用于查阅页面操作。想按一个完整案例学习知识库、Skill、MCP、子领域的组合，并接入自己的系统，请跟随[完整实操教程](ops-onboarding.md)，其中提供独立练习材料和真实接口替换步骤。

## 开始前准备什么

你需要一台安装 **Node.js 22.16 或更高版本、Python 3.12 和 uv** 的电脑、项目源代码和终端。Node 是后端运行环境，npm 用于安装依赖和运行项目脚本。Node 22 的 `node:sqlite` 可能打印实验性提示，这不等于启动失败。

要得到真正的回答，还需要兼容 Responses SSE 的模型 Base URL、模型 ID，以及服务要求的 API Key。要查询真实服务状态，还需要一个可连通的 MCP Streamable HTTP 服务和它要求的 Token。知识库、Skill、MCP 可以逐步添加，不必一次全部准备好。

## 第一步：启动项目

在终端进入本项目根目录，也就是包含 `package.json` 的文件夹。先确认版本：

```sh
node --version
npm --version
```

首次安装并启动：

```sh
npm ci
uv sync --project agent-worker --frozen
npm run agent:check
npm run dev
```

`npm ci` 按 `package-lock.json` 安装依赖，适合接手时复现；它会重建 `node_modules`。`uv sync --project agent-worker --frozen` 安装锁定的 AgentScope；缺少 Python/SDK 时启动会失败。运行时不要关闭终端；按 Ctrl+C 停止开发服务。

打开 `http://localhost:5173`。后端默认在 `http://127.0.0.1:3001`，前端会代理 `/api` 到该地址。直接访问 `http://127.0.0.1:3001/api/health` 应看到 `{"ok":true}`。

开发页面在 5173，不是 3001；3001 只有在构建了 `dist/` 后才会同时提供生产页面。`npm run preview` 仅预览静态构建，不负责启动 API。

以启动终端打印的实际地址为准：5173 被占用时 Vite 可能改用 5174。不要同时保留多套开发进程；前端即使启动在 5174，仍默认代理到 3001。更新代码后若上传 Skill 显示“接口不存在”，先检查 3001 是否仍由旧后端占用，正常停止旧进程并重新运行当前代码；刷新前端不会让非 watch 模式的旧后端加载新接口。

如果只想阅读项目，无需运行上述命令，双击 `docs/site/index.html` 即可打开官网。官网与实际工作空间是两份页面，官网中的交互演示使用固定教学内容。

## 第二步：创建首个管理员

首次打开工作空间，会显示“初始化工作空间”。填写用户名、显示名称、密码，点击“创建管理员并进入”。

- 用户名：3–40 位字母、数字、点、下划线或连字符。
- 显示名称：用于界面识别，最多 60 字符。
- 密码：12–200 字符。没有预置账号或默认密码。
- 创建成功后会直接登录，不必再输入一次密码。

如果已有用户，页面显示登录；不能再次初始化。若配置了环境变量初始管理员，数据库为空时启动就会创建用户，此时直接登录。只要数据库已有用户，环境变量不会覆盖原账号。

普通成员由管理员在“工作空间设置 → 用户管理”创建，没有自助注册入口。
生产初始化另需部署管理员提供 SETUP_TOKEN，或预置初始管理员。企业 gateway 模式通过签名 MFA 网关登录，页面会提示检查企业身份。生产配置见 [生产治理](production.md)。

## 第三步：配置模型

点击左下角“工作空间设置 → 模型服务”（小窗口从顶部导航按钮进入），填入：

| 字段 | 怎么填 | 常见错误 |
| --- | --- | --- |
| API 协议 | 固定使用 Responses API | 服务商不支持 Responses API |
| API Base URL | 服务商给出的 API 前缀，例如 `https://api.openai.com/v1` | 填到了完整 `/responses`，系统又追加一遍 |
| 模型名称 | 服务商准确的模型 ID | 填了展示名称，服务端找不到模型 |
| API Key | 服务商密钥；无需认证的本地模型可留空 | 错密钥、额度不足、密钥无模型权限 |
| 默认问答强度 | 快速、均衡、深度；服务商默认不发送强度参数 | 模型不支持所选 `reasoning.effort`，可改用服务商默认 |
| Temperature | 0–2，默认 0.3；留空不发送该参数，使用服务商默认值 | 模型不支持此参数时仍填数值，导致请求被拒绝 |
| 流式首字节超时 | 1–120 秒，默认 90 秒 | 设得过短会把供应商排队或慢启动误判为失败 |
| 流式静默超时 | 60–600 秒，默认 180 秒；填 0 禁用 | 只限制已开始响应后的数据间隔，不替代整轮超时 |

先点击“保存模型配置”，再点“测试已保存配置”。测试发送一条“请只回复：连接成功”的普通模型请求；它不测试知识检索或 MCP 工具能力。要验收工具兼容性，还需完成后面的工具实测。

后端保存加密后的 API Key，界面只看到“已有密钥”状态。编辑时留空表示保留原密钥；勾选“清除已有 API Key”才清除。界面保存配置整体优先于环境变量，不会逐字段从环境变量补齐。

没有保存过配置时，可用 `MODEL_API_TYPE=responses` 配合 `MODEL_BASE_URL`、`MODEL_NAME` 和 `MODEL_API_KEY` 选择 Responses；`MODEL_FIRST_BYTE_TIMEOUT_SECONDS` 与 `MODEL_STREAM_IDLE_TIMEOUT_SECONDS` 可覆盖 90/180 秒默认值。省略协议时默认 Responses；旧模型配置读取时按 Responses 执行，原配置和密钥不自动改写。新保存配置只接受 responses，MODEL_API_TYPE 的其他值会报错。Responses 支持文本对话与 MCP 函数工具调用，采用 `store:false` 和本地历史续传；输出长度由 `MODEL_MAX_TOKENS` 映射到 `max_output_tokens`。模型仍需支持函数工具调用，才能实际使用 MCP。

模型出口固定为 Responses SSE，所有请求都带 `stream:true`。供应商必须返回 `text/event-stream` 和合法完成终态；完整 JSON判为失败；符合条件的短暂断流、等待首个数据块超时或流中静默超时最多重试五次。每次尝试默认等待首字节 90 秒，收到数据后允许最长静默 180 秒，整轮仍受默认 420 秒限制。没有关闭流式或完整响应回退配置，详见[恢复规则](conversation.md#资源检索与模型)。

模型默认强度对应 `model_reasoning_effort`：快速 `low`、均衡 `medium`、深度 `high`。没有保存过模型配置时可设置 `MODEL_REASONING_EFFORT=low/medium/high`；不设置或 `none` 不发送参数。旧配置没有该字段时仍使用服务商默认。

未配置 Base URL 和模型 ID 时，对话会明确提示配置缺失。`configured=true` 仅说明这两个字段存在，不代表网络、密钥和模型一定有效。

## 第四步：建立第一份知识

进入“知识库管理 → 新建知识库”，填写名称、说明、领域、状态、使用范围和 Markdown 正文。Markdown 是一种纯文本排版方式，`#` 表示标题，`-` 表示列表。

可复制下面这段练习内容，标题设为“计费服务超时排查手册”，领域设为 `billing`：

```markdown
# 计费服务超时排查手册（教学示例）

## 适用场景
计费服务出现超时，需要先收集信息再判断原因。

## 建议检查顺序
1. 确认服务名称、环境、故障发生时间。
2. 查询当前服务健康状态和响应耗时。
3. 检查数据库连接池与下游依赖。
4. 将已观察事实和可能原因分开描述。

## 输出要求
提供观察事实、待验证假设、下一步建议，不自动重启服务。
```

这段内容用于学习流程，不能代替你的真实运维标准。保存后打开“详情”核对原稿和预览。刷新浏览器后资源仍存在，说明已保存到后端。

正文最多 200,000 字符；文件导入在前端另限制 200,000 字节。API 请求整体最多 1 MB。支持 Markdown / 文本导入；可填写文档版本、有效期与来源 URL，管理员可同步纯文本/Markdown 来源。没有 PDF 解析或任意网站抓取。

知识库的一条资源就是一份正文，不是上传后自动生成的多文档目录。名称、领域、描述也参与检索；写清对象名称和常用故障关键词有助于匹配。

## 第五步：写一个 Skill

进入“Skill技能”，点击引导区域的“上传 Skill”，选择 `.zip` 技能包。包根目录或单层文件夹中必须有且仅有一个 `SKILL.md`；可以同时包含 `references/`、`scripts/`、`assets/` 等配套文件。选择后自动检查并预览正文、文件列表和版本，名称与描述可在提交前调整。

也可以从新对话欢迎页点击「定制运维 Skill」进入 Skill 页面。ZIP 最多 600,000 字节，解压后总计最多 5,000,000 字节、单文件最多 2,000,000 字节、最多 200 个条目；`SKILL.md` 必须是非空 UTF-8 文本且最多 200,000 字节。拒绝路径穿越、符号链接、加密文件、重复路径和损坏包。可忽略 macOS 的 `__MACOSX/` 与 `.DS_Store` 元数据，但它们仍计入限制。`SKILL.md` 示例：

```markdown
---
name: billing-diagnosis
description: 计费服务排障流程
metadata:
  version: "1.0"
---
# 计费诊断流程

## 适用场景
用户请求排查计费服务故障。

## 输入条件
先确认服务名与环境；缺少时说明需要哪些信息。

## 执行步骤
1. 阅读已提供的相关手册。
2. 如有已授权的状态查询工具，查询用户指定服务。
3. 工具失败时如实说明，不编造当前状态。
4. 只提供建议，不执行重启或删除。

## 输出格式
观察事实 / 可能原因 / 下一步检查 / 知识来源。
```

支持可选 YAML front matter 的 `name`、`description`、`version` 或 `metadata.version`；未声明名称时使用文件夹名或 ZIP 文件名，未声明版本则显示“未声明”。完整原始 ZIP 保存在资源及版本历史中，可在详情中下载，沿用资源访问权限；包内正文只读，更改内容需重新上传 ZIP。历史纯文本 Skill 仍可编辑。

ZIP 上传始终先创建草稿（包括管理员上传），审核发布后才加载 `SKILL.md` 正文。配套文件随包保留，不自动加入模型上下文，也不会执行 Shell 或 Python 脚本。版本字段用于展示，不执行版本号递增或同名去重；当前没有独立线上/测试双槽位，编辑已发布资源会转为草稿，需要重新发布。

发布入口在该 Skill 的“详情 → 版本历史与发布 → 审核并发布已保存版本”。列表中的“已启用”只表示启用状态，不等于已发布；请在详情顶部核对“草稿”或“已发布”。下载原始 ZIP 也在详情中。

通用 Agent 会加载当前用户可读、启用且已发布的 Skill。成员创建为草稿，需管理员在版本历史区域发布；编辑后重新审核。过多或冲突的 Skill 会一起进入上下文，需要隔离时使用子领域。单条 Skill 只取前 12,000 字符。

“只提供建议”属于模型指令；限制真实工具能力应同时依靠 MCP 允许列表，不能仅靠一句提示词保证远程操作范围。

## 第六步：连接 MCP 工具

这一步需要管理员和一个真实 MCP 服务地址。项目本身是 MCP 客户端，不内置你公司的监控平台，也没有自动把普通 REST API 变成 MCP 的转换器。

1. 进入“MCP服务 → 添加服务”。
2. 填名称、说明、Streamable HTTP 地址，例如你的 `https://tools.example.com/mcp`。
3. 服务要求认证时填写 Bearer Token；默认私有，按实际使用者设置权限。
4. 先保存。重新打开该服务“详情”。
5. 点击“连接并发现工具”。后端握手并读取工具名称、说明与参数 schema。
6. 勾选工具，并为每个工具填写 toolPolicies 的风险、用户/角色、环境与参数范围，再点击保存。可填入只读策略模板后按实际工具核对。
7. 回到前台提问，检查回答下方是否出现实际的服务名 / 工具名摘要。

未勾选或没有策略的工具不能执行。发现列表不等于授权。右下角“执行与审批”中心可以提交确定的工具参数；写操作先生成计划，生产/高风险需要另一位管理员审批。旧 `/api/mcp/:id/call` 测试接口只允许已授权只读工具。

执行中心支持键盘操作：Tab / Shift+Tab 在弹窗当前可用控件之间循环，折叠的通知、工具操作或 Runbook 保留可聚焦标题，内部隐藏表单不参与循环。按 Enter 展开后可继续进入表单，按 Escape 关闭并回到打开入口。

MCP Token 留空保留已有值，勾选清除才删除。只支持 HTTP(S) 地址，不支持 `stdio` 本地进程、旧版 SSE endpoint 或 OAuth 登录跳转。

### 先浏览工具清单

在 Skill 或 MCP 页面点击「查看工具清单」，右侧抽屉汇总当前账号可读 MCP 服务的已保存允许列表。输入工具名或服务名即时搜索，或选择某个服务筛选；点击「查看服务配置」进入现有详情表单。关闭、点击遮罩或按 Escape 返回原列表，键盘焦点回到打开入口。

卡片区分只读查询、可执行变更、高风险变更，以及缺失策略的「暂不可执行」。服务停用单独标记。只读交互无需写入审批；写入交互需审批与核验，生产/高风险变更还需另一位管理员批准。工具数量按每个服务的允许列表去重统计，包含停用和未配置策略的条目。

这是配置目录，不发起远程发现或试调用，不展示实时在线状态，也不是当前用户可调用工具总数。实际执行仍检查身份、环境、参数、绑定和审批。项目没有参考界面中的独立内置工具市场；平台能力与已接入 MCP 的区别见 [上下文与工具](context-and-tools.md)。

## 第七步：按需建立子领域

如果通用 Agent 的多个 Skill 互相干扰，进入“子领域Agent → 创建子领域”。例如名称“计费排障”，正文说明职责，再勾选计费手册、计费 Skill 与所需 MCP。

子领域限定的是资源 ID 集合，不会复制内容，也不会绕过使用者权限。**绑定列表为空表示不使用该类资源**，不会自动回退到通用 Agent 的全部资源。

保存并发布后在前台新建对话、发送前选择子领域。会话建立后 Agent 选择器锁定，需要新建对话才能切换。已有会话每轮读取当前发布状态；编辑后成为草稿，重新发布前不能继续使用。

管理员首次创建子领域时当前实现直接发布；成员创建或任何人修改已有子领域后为草稿。需要手动发布时，进入“详情 → 版本历史与发布”，审核已保存版本。不要把 ZIP Skill 的“首次上传始终为草稿”套用到管理员新建子领域。

## 第八步：完成第一轮对话

输入框旁的“选择强度”菜单提供快速、均衡、深度，选中后入口显示对应档位；配置了系统默认时标明“系统默认”，也可恢复系统默认或使用服务商默认。选择保留到当前聊天组件卸载，刷新、新建/重新打开会话后恢复系统默认；已保存回答保留当轮档位。生成中禁止切换。强度同时用于本轮分析、工具往返、重试和独立复核，不修改系统配置；更深档位可能增加等待和用量，不保证结果质量。

输入区的“独立复核”默认关闭。开启后，本轮分析答复会交给另一个没有工具权限的 Agent 检查请求与已有证据，增加一次模型请求和等待时间。只有复核通过才展示分析答复；否则会提示未通过或未完成，可展开“分析→复核”查看原因、阶段请求数与 token，并下载结果 JSON。复核不是人工批准，也不代表业务健康；此前已经完成的工具查询仍保留在执行中心。该开关按次发送，不改变定时任务或管理员增强配置，写计划仍需人工审批。

点击管理页面右上角“返回前台”。如果正在查看旧会话，可点击左侧“新建对话”创建新会话。

窗口宽度不超过 760px 时，常驻侧栏收起，通过顶部「打开导航」访问后台页面、最近 30 个本人会话、设置和「新建对话」。导航抽屉支持 Tab 焦点循环与 Escape 关闭，打开和关闭导航不会清空正在输入的草稿。跳转后台页面或新建对话会卸载当前聊天界面，未发送草稿与附件不会持久保存。

欢迎页的问题示例只填入输入框并聚焦，不自动发送。聊天侧栏的「查找对话」过滤本人已加载的会话摘要，也可直接进入资源、文档与入门。当前对话标题、执行与审批和后台入口位于精简顶部；聊天不再显示模拟窗口标题栏。用户问题以灰色气泡右对齐，助手以连续正文回答；上滚阅读时可点击「返回最新消息」。知识检索与独立复核收在输入框内，输入随草稿自动伸展，长内容在框内滚动，320px下控件换行。后台全屏按钮继续沿用浏览器支持情况。

点击或用键盘进入问题输入区时，整个输入卡片仅显示一条蓝色外边框，文本区域不再叠加内框或外圈光晕。附件、Agent 选择和发送按钮各自保留键盘焦点描边。

底部 Agent 入口采用带边框、图标与箭头的按钮；点击后打开菜单，显示名称、用途说明和当前选中勾。即使只有“通用”，也可查看其用途。新会话可选择当前可见且已启用的 Agent；已有会话显示锁图标，正在生成时也禁用切换。关联的 Agent 停用或不可见时保留原关联，并显示已停用/不可用提示。菜单支持方向键、Home/End、Enter、Escape与Tab，外点关闭；窄屏自动调整位置，长名称截断，较多选项可滚动。

1. 选择“通用”或刚创建的子领域。
2. 保持“知识库检索”开关打开。
3. 输入“计费服务超时应该按什么顺序排查？”先验证资料问答。
4. Enter 发送；Shift+Enter 换行。输入法正在选词时不会误发送。
5. 页面依次显示检索、连接工具、生成回复等进度，等待最终答案。
6. 检查知识来源徽标。如果没有来源，先核对权限、启用状态、子领域绑定和关键词。
7. 如果已接 MCP，再问“请调用已授权的状态查询工具检查 billing，并结合手册解释下一步”。实际调用是否发生取决于模型返回的 `tool_calls`。
8. 检查工具摘要和回答是否一致；工具显示错误标记时，不要把生成文本当成成功执行证据。

MCP 握手/发现失败会在消息下方保存“未取得实时数据”提示，列出服务名和重新检查连接的说明，刷新会话后仍可查看。回到 MCP 详情点击“连接并发现工具”，恢复后重新查询。发现失败尚未执行工具，因此不会生成工具步骤；已有目录缓存时，故障也可能在实际调用阶段显示为工具失败。不能仅凭模型文字或缺少失败提示判断已取得实时数据，应核对本轮实际工具摘要。

再追问“刚才的结果意味着什么？”会继续同一会话，后端读取最近消息作为上下文。新建聊天则不携带其他会话内容。

最终答案是 Markdown，经 `marked` 解析和 DOMPurify 清理后显示。知识来源徽标意味着片段被提供给模型，不保证每句话都有精确对应引用，更不是自动事实核验。

管理员启用证据报告后，回答下方会出现“本轮证据”。点击或用键盘展开，可查看数据缺口、实际工具步骤编号/状态、资料版本，并通过“导出证据 JSON”保存快照。报告记录回答生成时的事实，后续审批和结果核对请去执行中心查看；“回答已生成”不代表服务健康。报告不含工具参数、原始返回或问答正文。

若看到“本轮省略了较早消息”，说明管理员启用了历史预算裁剪。把本轮需要的任务 ID、区域和限制重新写在问题里；系统不会把省略的历史自动总结或永久记住。开关与回退方法见 [运行指南](agentscope-runtime.md)。

## 文本附件怎么用

点击输入框旁的回形针，选择 `.txt`、`.md`、`.json`、`.log`、`.yaml` 或 `.yml` 文本。文件最多 60,000 字节，问题与附件拼接后的全文最多 20,000 字符。

浏览器读出文本，拼接到问题后面：`附加文档「文件名」：...`，作为同一条消息提交。没有单独的文件上传接口、附件库、图片识别或 PDF 解析；附件不会自动进入知识库。

附件会参与当前问题的检索词提取，也会作为用户消息保存。想长期重复使用，应把合适内容整理到知识库，而不是每次附带大文件。

## 第九步：创建定时任务

先用普通聊天验证你的指令能独立执行，然后进入后台“定时任务 → 创建定时任务”。

| 字段 | 填写方法 |
| --- | --- |
| 任务名称 | 例如“每日计费服务巡检” |
| 完整任务指令 | 写明服务、环境、时间范围、工具要求和输出格式，不写“继续刚才的操作” |
| 处理 Agent | 通用或有权限的已启用子领域 |
| 调度类型 | 指定时间单次执行，或 Cron 周期执行 |
| Cron | 例如 `0 9 * * *`；字段依次为分、时、日、月、周 |
| 时区 | 默认 `Asia/Shanghai`；按该时区计算 Cron |
| 单次执行时间 | 浏览器本地时间输入，前端转换为 ISO 时间发送 |

示例完整指令：“查询 billing 服务当前健康状态，根据计费排查手册生成观察事实、待核实问题和下一步建议。没有状态查询工具或工具失败时，明确标记未取得实时数据。”

保存后点“立即执行”，在“记录”中等待结果。记录每 5 秒刷新，可点击“查看会话”。每次执行都会新建独立会话，不能继承你创建任务前的聊天历史。

- “暂停”停止未来自动触发；不会中止当前执行。
- 已暂停任务也可以“立即执行”。
- 手动运行不改变下次自动计划时间；单次任务手动试跑成功后，原计划仍可能再执行一次。
- Cron 恢复启用时从当前时间计算下一次，不补暂停期间的每一次。
- 删除任务会删除其执行记录，但关联会话、执行证据与通知快照保留；已入队消息仍会投递。
- 页面支持创建、通知设置、暂停 / 启用、立即执行、删除；没有修改已有任务指令 / Cron 的编辑接口，需要新建替代任务。
- 当前没有聊天创建任务的内置工具。任务创建或“通知设置”中可选择企业微信/Webhook 渠道、推送条件与恢复通知。

通知中心与定时任务同级：管理员先创建渠道并发送测试消息，再在任务中启用。异常模式必须配置实际工具字段的正常条件；没有匹配证据、数据过期或未完成执行时显示无法判断。执行记录分别显示执行、巡检与投递状态。配置步骤、消息协议与边界见[巡检通知与企业微信](notifications.md)。

## 管理资源和成员

资源列表可按名称、说明、领域、所有者搜索，知识列表另有领域筛选。搜索后点击“查询”，重置恢复筛选。资源列表客户端分页，每页 20 或 50 条。

Skill / MCP 的“我的”页签显示当前用户可管理的资源，不只包含自己创建的；“全部可用”显示所有可读资源。这里的“全部”仍受权限限制。

在资源“指定可用用户与管理人”里按 Ctrl / Command 多选：可用用户能使用，管理人可维护；公开表示已登录工作空间成员可读，不表示互联网匿名访问。

管理员可创建成员、启停成员、调整角色；自己的账号不能被自己停用或降为成员。管理员重置密码由 API 支持，当前设置界面没有重置他人密码的按钮。停用或重置密码会撤销该用户的已有登录会话；角色调整会在后续请求读取当前数据库角色。

“我的账号”可修改自己的密码，其他登录会话失效，当前浏览器获得新 Cookie。退出仅撤销当前登录会话。

## 查看会话和审计

聊天左侧 Recent 最多显示当前用户最近 30 个会话。后台“会话管理”最多读取最近 300 个可见会话，可按 Agent、关键词、日期过滤。管理员可以查看其他人的会话，但只能查看，不能继续发送。

会话详情展示用户消息、助手消息、错误、知识来源和工具摘要。执行中心另保存步骤、脱敏结果和核验，不保存模型隐藏推理。会话删除有 API，但当前会话管理页面没有删除按钮。

“工作空间设置 → 审计日志”仅管理员可用，列出最近 200 条事件。审计包含关联 ID 与脱敏参数/结果，不记录已识别的密码和密钥明文。完整 detail 可从审计 API 查看，独立导出与哈希检查见生产治理章节。

## 入门完成自检

- 能成功登录，并知道谁是管理员。
- 模型测试通过，普通聊天能得到真实返回。
- 添加的知识刷新后仍存在，相关问题能看到来源。
- Skill 改变了回答组织方式，且明白它不是脚本执行器。
- MCP 发现并授权后，真实聊天能看到工具摘要。
- 子领域空绑定会限制资源，成员无法读取未授权私有知识。
- 定时任务试跑有记录和独立会话。
- 知道数据目录在哪里，知道备份必须包含 `master.key`。

如果其中一步失败，按 [排错指南](operations.md) 对应症状检查，不要连续重复提交可能产生外部副作用的工具请求。

## 管理 Agent 增强

管理员点击右上角头像，在「工作空间设置 → Agent 增强」选择已发布的子领域、通用 Agent 和增强选项，保存草稿，运行本地 SDK 预检，再启用增强。保存不会改变当前生效版本。点击「暂停增强」后，新轮次恢复原始历史/检索模式并关闭证据报告；范围外也使用该增强基线。所有对话始终由 AgentScope 编排，在途执行不重放。

Python 3.12 与锁定的 AgentScope 是必需运行依赖。预检不调用真实模型或 MCP，不代表业务验收通过。资源发布、停用和权限规则始终生效。完整步骤、并发冲突/过期处理、排队边界和人工验收命令见 [AgentScope 运行指南](agentscope-runtime.md)。
