# 公司沙箱中的独立应用 PoC

## Why

用户希望按已推荐的最短验证路径，在公司 Agent 沙箱平台真实运行本项目，并明确要求不动生产环境；后续明确授权使用本地保存模型，并允许跳过 MCP。项目已有 Node + Python 3.12 / AgentScope 镜像，但平台通用模板、持久工作区、镜像启动方式和 HTTP Pod Preview 与现有部署约定不同，需要用全新测试实例核实可行性。

## What Changes

- 新增仅包含受控源码与构建结果的沙箱 PoC 打包/启动材料，不把现有 `.data`、`.env`、模型密钥、DTS 配置、任务或通知渠道打入源码包或镜像。
- 使用专用 Python 3.12 环境；复用项目 Dockerfile，或在独立测试实例内按锁定依赖安装同版本 Worker，不把平台默认 Python 3.14 当作兼容环境。
- 为默认 Node24 / Python3.14 的 Linux x86_64 测试实例新增私有运行时安装脚本：官方 Node22.23.1/SHA256、uv0.11.26、Python3.12，安装到实例本地 `/home/sandbox/poc-runtime`，不替换系统版本；源码归档、数据库和私有模型仍在持久 `/workspace`。
- 为新实例创建全新数据目录和测试管理员，绑定持久工作区 `/workspace`，通过可达的端口 3001 Preview 验证健康、就绪、首页和登录。
- 按用户授权只读导出本地保存的单个模型至新实例独立 0600 JSON，仅注入测试进程，不修改原模型或复制原数据库/主密钥；只允许该模型精确单一 origin。
- 在隔离测试环境验证真实 Worker、模型流式对话和实际进程重启后的数据恢复；本机受控模型作为备用工程验证。MCP / DTS 明确排除本轮，不迁移连接器、不调用真实 DTS。
- 新增部署说明、OpenSpec 与本轮验证记录，区分本机验证、公司平台实测、真实模型和生产部署的证据范围。

## Impact

本轮不改变产品 API、数据库 schema、现有生产校验或旧部署配置。仅创建新的测试实例和新工作空间；获准的本地模型配置只读提取，不改变原工作空间，不启动旧任务、不发送生产通知、不访问生产 DTS。HTTP Pod Preview 只作为 `NODE_ENV=development` 的隔离 PoC 入口；正式生产模式仍要求 HTTPS、Secure Cookie、外置主密钥和明确出口规则。PoC 镜像补齐账单静态依赖 `scripts/model-billing.mjs`，不修改根 Dockerfile 或既有部署。

自定义镜像发布、平台 bootstrap、UID/PVC 写权限、SQLite WAL/锁语义、进程及实例生命周期和测试网络出口必须逐项实测。未完成项目保持待验收，不能用本地 fixture 或历史报告替代目标平台证据。
