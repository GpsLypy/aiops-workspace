# AgentScope 独立代码沙箱协议与负面验收

## 现状与风险

AgentScope Python Worker 执行的是部署者信任的 SDK 代码。它虽按轮使用子进程和私有临时目录，仍与应用共享系统用户、应用源码和网络能力；现有 `aiops` 镜像还包含 `/app`。将模型生成或用户上传的代码交给该 Worker，会越过当前 MCP 工具策略和文件/网络边界。

## 本次范围

1. 为未来独立代码工具定义提交、身份、资源、隔离、取消、产物及审计协议，并列出威胁和验收门槛。
2. 增加一个仅运行内置合成 Python 探针的本地 Docker 负面验收入口。探针固定镜像 ID，核对容器配置、应用文件可见性、禁网、临时盘跨轮残留和强制取消回收；失败退出 2。
3. 保留产品默认状态：无代码工具、无上传执行 API、无 Agent 自主代码执行能力。本轮探针通过也不等于生产可用。

## 依赖与放行条件

需要独立、无应用代码和凭据的最小镜像，并按 digest 固定；独立 broker 运行在应用容器之外，应用进程不得接触 Docker socket。生产候选还需明确 rootless/user namespace、seccomp/LSM、宿主内核风险、制品扫描/审批和租户数据访问策略。负面测试须在目标部署运行时重复，不能以开发机 Docker Desktop 代替生产验收。

真实质量样本和保存模型配置的验收属于并行门禁，本提案不解除其阻断状态。
