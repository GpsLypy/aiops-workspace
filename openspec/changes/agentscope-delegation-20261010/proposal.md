# AgentScope 自主委派与可解释全景

## 为什么

当前子领域仅绑定指令与资源，独立复核是固定顺序；主 Agent 无法自主拆分任务。现有全景也无法表达子任务身份、上下文隔离与结果回传，用户难以看清多 Agent 的实际处理流程。

## 变更

- 用户明确开启允许委派后，向主 Agent 提供内部 delegate_agents 工具。由模型选择可见且已发布的子领域或通用 Agent，创建独立 AgentScope 上下文处理只读子任务；批次最多3项、每轮最多4个子任务、深度1、全局模型轮次12，保留现有主分析和复核上限。
- 子任务继承执行身份、目标绑定、预算与取消，并取主任务授权资源和子领域绑定的交集；不提升权限、不派生写审批或通用脚本。
- 加入 schema v7 的加密委派生命周期记录，关联父执行；重启标记中断且不重放，幂等回读复用原结果，备份/换钥同步覆盖。
- 全景展示实际委派、子 Agent、上下文、预算、模型、工具、回传与汇总节点和依赖，按父子身份分组，保留旧图兼容、JSON导出和窄屏键盘阅读。

## 边界

默认不委派；新聊天可显式开启，定时任务保持当前行为。首版单层只读委派，没有递归、后台脱离父执行继续运行、任意工具授权、跨用户共享记忆或模型私有推理展示。全景展示记录到的处理事实，不推断模型思考过程；不把工程验证当作真实模型质量或生产上线。
