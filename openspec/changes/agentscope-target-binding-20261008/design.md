# 设计与验收边界

## 目标来源

`targetBinding={resourceId,tool,environment,arguments}` 由认证用户在聊天本轮或任务配置中显式确认。arguments 只接受 1–8 个具名非空标量字段；不接受 null、数组、嵌套对象或危险属性名。新轮聊天重新确认；任务保存绑定并在每轮按当前资源策略复核。它参与加密执行输入和幂等摘要，不写入公开 trace 或审计原文。

## 执行门禁

只读工具可配置 `requiredTargetFields`。有绑定时先在连接 MCP 前核对可见资源、工具、环境、策略，只向模型提供所选的一个连接器和工具。模型生成的整批工具调用在执行前验证；每次 callStep 再核对最新身份、资源、静态范围、Schema 与目标字段集合和值。额外字段及跨工具调用也拒绝。没有目标策略的工具维持原行为；固定工具、Runbook 和 MCP 直接测试仍按原流程执行。受保护工具缺绑定时拒绝调用，普通聊天问题仍可不配置目标。

## DTS 与任务迁移

DTS 区域授权保留任意有效 jobid，但每轮目标必须确认 jobid 字符串、business_domain 和 area_name。新建资源带三字段策略；现有资源通过核对地址、Token、只读等级、域和区域的 `sync-policy` 增加该策略与审计修订，不随代码部署自动触碰真实数据。本机工作空间已在备份和存量任务核对后显式同步至修订 3，三条旧任务仍停用且绑定为空。SQLite v6 为 tasks 增加可空 target_binding；任务所有者在页面补配，调度不从 prompt 或巡检条件推断目标。其他实例升级前仍要核对现有任务，避免受保护查询预期失败。

## 不宣称的能力

绑定只约束用户明确选择的结构化目标，不能证明自然语言与选择在语义上相同，也不识别问题或附件中的目标。单轮只支持一个工具、一个目标，且必须由策略覆盖所有决定查询对象的字段。合成 fixture 验证前置拦截，不证明真实模型识别率、真实 DTS 端到端或人工质量评分。
