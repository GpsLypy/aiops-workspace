# DTS MCP 独立公司沙箱部署

用户要求把既有 DTS MCP 独立部署到公司沙箱，逐步落地。保留原 Mac 服务和助手 PoC，复用已有只读工具，不部署 DTS 后端或扩大业务权限。

独立项目、Linux UID1000、持久工作区、锁定最小 Node 依赖；MCP 保持 127.0.0.1，通过 SSH 本地转发供客户端调用。私有配置与源码包分开，独立 MCP Token，不复制应用数据库或主密钥。先验证网络，再完成真实 SDK、鉴权和范围拒绝、进程恢复；应用端完整对话另行记录实际结果。

用户续轮明确整个助手项目只保留Responses：移除Chat Completions请求/解析分支、前端协议选择和脚本选项，保留目标绑定/权限/持久执行。旧保存配置内存归一到Responses、不改写凭据；新旧协议输入拒绝；后续用户要求只保留Responses SSE，所有模型请求固定stream:true，移除完整JSON分支/回退/开关并拒绝非SSE响应，连接测试与复核共用同一路径。默认及沙箱受控模型、工具和复核fixture统一迁移，真实沙箱重部署后重新记录端到端结果。
