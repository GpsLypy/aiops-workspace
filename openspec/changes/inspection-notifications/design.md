# 设计

## 数据与语义

SQLite 显式升级至 v4。notification_channels 保存加密 URL 和凭据、指定使用成员、启停与配置版本；notification_events 保存脱敏消息快照及唯一 source_key；notification_deliveries 为每个事件/渠道保存独立状态、稳定幂等键、次数、下次时间和错误。任务本身保存通知规则和巡检判定规则，避免维护两套订阅。保留旧 notifications 表及环境变量出口。

任务的执行状态、业务结论、投递状态独立。巡检结论由实际 tool_steps 的结果和显式规则判定，匹配服务、工具与可选参数条件；不解析模型文字判断健康。规则是正常条件：eq/ne/数值比较/ISO 时间新鲜度。缺字段、缺调用、失败、脱敏值、类型不符、过期数据均为 unknown。未配置规则的普通报告显示未判定，只能选择每次推送。

任务结束及事件/投递插入同一事务。每个渠道独立抑制重复异常，变化立即通知，持续异常按 repeatMinutes 提醒；恢复开关控制正常恢复通知。编辑规则后重置抑制状态，运行中禁止编辑。进程重启和过期租约补记中断并入队，不重新执行任务。

发送在后台处理，5 秒超时，最大 8 次自动尝试，退避上限 1 小时并尊重有界 Retry-After。网络、408/429/5xx 可重试，其他 HTTP 错误及机器人业务错误终止。投递至少一次，通用接收方按 Idempotency-Key 去重；群机器人可能重复。对端确认成功才标已送达。重新发送沿用消息和幂等键，不重新巡检。

渠道仅管理员创建/编辑，成员仅使用明确授权渠道并查看自己的消息。每次发送重新检查用户启用、渠道启用、使用权限和配置版本；配置改变后旧消息失败，人工重发确认使用新配置。URL/凭据加密保存，编辑时空白保留，不回显。使用 safeFetch 的出口控制、DNS 固定、禁止重定向。密钥轮换覆盖新增密文。

## 页面与视觉

通知中心与定时任务同级；两个页签为推送记录、通知渠道。任务创建/编辑内直接配置结果通知和正常条件。投递详情保留消息预览、失败原因、重试时间、执行记录关联，支持状态筛选和分页。

延续工作空间浅色紧凑界面：背景 #f7f9fc、表面 #ffffff、正文 #233047、主色 #265dff、成功 #178354、警示 #ae6717。标题和正文沿用系统中文无衬线字体，时间/编号使用 ui-monospace。特色是同一条执行记录中并列展示执行、巡检和投递三个状态，避免单一红绿标记误导。窄屏堆叠表单与卡片，键盘焦点可见，不添加无用途动效。
