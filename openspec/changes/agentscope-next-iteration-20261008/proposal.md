# AgentScope 下一轮：质量证据、观测关联与运行时临时文件归属

## 核查结论

AgentScope 入门所列的三个方向仍有实际缺口，但“尚未实现”只适用于完整目标。现有系统已具备本地合成评测及版本摘要/人工复核验收门禁、单轮脱敏问答全景、每轮 Worker 子进程与 Node 工具门禁。没有真实问题和失败样本的可审查台账、已完成人工标注、跨请求 Agent 阶段指标、外部 OpenTelemetry 链路，也没有运行不可信代码的操作系统沙箱或租户隔离。截图的优先列表漏了已知 P0：授权范围内换错目标仍可能查询，查询前目标绑定尚未实现。

## 本轮目标（2026-10-08）

1. 将质量样本来源、人工标注与当前候选摘要做可复核的本地校验；缺少真实样本或标注时明确阻断，不借合成语料宣称质量放行。
2. 用实际完成的脱敏 trace 汇总低基数阶段耗时，并给一次运行和各节点可持久回看的关联 ID；不把配置价格估算当供应商账单。
3. 将 Worker 的临时文件创建限制在本轮私有工作目录内，并验证正常/故障收尾；不把同 UID 进程边界称作沙箱。
4. 更新入门页、运行/开发文档、验证记录和离线官网，使已交付切片与后续目标清楚分开。

## 后续门禁

下一阶段先把用户确认的对象/环境绑定到只读工具参数，在调用前拒绝授权内偏移、歧义目标和工具结果中的改目标指令，并以合成攻击语料及真实授权场景验收。真实质量放行需要授权且脱敏的问题/失败样本、逐条人工评审和真实模型复测。外部 OpenTelemetry 需要 Collector/出口配置及脱敏、采样、故障策略的独立验收。文件、网络与代码执行需要独立容器或 microVM 的威胁模型、协议、默认禁网、只读根文件系统、资源限额、产物审批和负面测试；本轮不开放任意代码执行入口。

同日续轮已完成单工具、单对象的结构化只读目标绑定和本地回归，见[目标绑定方案](../agentscope-target-binding-20261008/proposal.md)。本机真实 DTS 资源已在备份/恢复和旧任务核对后显式同步至修订 3；真实模型/上游场景验收另记[验证记录](../../../docs/verification.md)。用户随后授权从本机历史提取脱敏候选；一条原工作空间 user-role 消息因作者与场景来源未核实，标为 `historical_candidate`，不计入真实用户问题。`real_problem` 和人审门禁继续阻断；其余门禁保持待办。

后续又完成默认关闭的[可选 OTLP 出口](../agentscope-otel-export-20261008/proposal.md)及本机官方 Collector 接收验证，并建立[独立沙箱协议与合成探针](../agentscope-sandbox-protocol-20261008/proposal.md)。这些开发机证据不解除真实质量样本、人审、保存模型端到端验收、生产 Collector 或生产沙箱门禁。

质量续轮增加两条摘要驱动的重构问题，仅使用专用合成任务 ID 和临时 DTS 链路验证当前候选的自动边界；跨区域案例在模型调用前拒绝，不代表历史换目标行为已重放。报告可逐条绑定人工答复复核，但重构问题复核通过也不能替代真实用户问题来源或 v3 发布评测。保存模型在真实 DTS 查询后的第二次生成存在波动，新增默认关闭的固定字段模型请求诊断以区分阶段、耗时和取消来源；未改变超时或自动重试。
