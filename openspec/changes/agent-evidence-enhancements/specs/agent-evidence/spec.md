# 第四期增强需求

## ADDED Requirements

### Requirement: 独立可回退

三个增强 MUST 在启动时分别配置，默认 recent/ranked/false，适用于两运行时。请求不得覆盖部署配置；回退不得要求 schema 降级。

#### Scenario: 关闭报告后读取旧会话

- WHEN 报告配置关闭后重启兼容构建
- THEN 新消息不生成报告，旧消息的版本 1 报告仍可读取和导出

### Requirement: 完整历史轮次与预算

budgeted MUST 只处理初始文本历史，在近 30 条窗口内移除孤立回答和最早完整 user 轮次，保留当前问题；MUST 明确提示省略。系统、工具定义及当前问题放不下时必须在模型请求前拒绝。

#### Scenario: Responses 工具闭环

- WHEN 初始历史已裁剪且模型要求工具调用
- THEN 当前调用、工具返回与 opaque reasoning 原样续传，后续请求仍受原累计预算和六次上限约束

### Requirement: 授权范围内多文档检索

diverse MUST 仅选择通过 ACL/启用/有效期/绑定过滤的候选，优先不同文档、再补非重叠片段，每文档最多两段，总计最多五段。

#### Scenario: 公开子领域绑定私有知识

- WHEN 普通成员使用该子领域
- THEN 未授权私有知识不得进入模型、消息来源或证据报告；关闭知识检索时全部来源为空

### Requirement: 证据与诊断分离

报告 MUST 从本轮持久工具步骤和来源构造，标注消息生成时点，业务状态保持 not_assessed；不得从模型文字推导健康结论，不导出问答正文、参数、原始返回、连接地址或凭据。

#### Scenario: 无工具或审批后回看

- WHEN 本轮没有成功工具证据
- THEN 报告明确列出该限制，模型声称正常不改变判定
- WHEN 报告生成后计划被批准执行
- THEN 消息快照保持原待审批状态，并指向执行中心查看最新状态，不冒充实时报告

### Requirement: 可访问的持久回看和本地导出

聊天 MUST 支持报告键盘展开、刷新回看、320px 布局和本地 JSON 下载；读取沿用会话 ACL。

#### Scenario: 其他普通成员访问报告

- WHEN 用户尝试读取不属于自己的会话
- THEN 会话接口拒绝，不提供独立可绕过 ACL 的报告端点
