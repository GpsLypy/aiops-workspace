# 设计

## 学习路径

工作空间「AgentScope 入门」增加「学习与面试」视图，按真实链路组织六个交互主题：Agent/ReAct、上下文与检索、MCP/权限、持久执行、独立复核、观测与评测。完整文档拆为八个学习单元，将 Worker 隔离和流式单独展开，另提供十组面试问答及两个工程取舍案例。

每个主题包含原理、源码文件与函数、已有本地 fixture 命令、预期观察及面试问题。答案初始折叠；笔记和自评仅保留在当前学习视图，可导出 Markdown。导出不代表完成了测试，课程切换保留本次记录，离开视图或刷新清空。无数据库迁移或新 API。

## 视觉与交互

遵循 frontend-design 并延续入门工作台的蓝白品牌。颜色角色沿用主蓝 #315fff、正文 #202736、次要正文 #69758b、分隔 #e2e8f2、浅底 #f6f8fc 与白色 #ffffff；标题用 Avenir Next / PingFang SC，正文用现有系统中文无衬线，文件/命令用系统等宽字体。左侧顺序目录、右侧实验手册突出“源码—实验—解释”的对应关系，窄屏上下排列。原生按钮、details、label 控件提供键盘与焦点支持，不以动效传达必要信息。

初步方案不采用仪表盘式达成率或成绩认证：自评无法证明用户已经掌握。只呈现用户自己填写的练习记录及明确的内存保存边界。

## 文档与持续推进

docs/agent-learning.md 和 docs/agent-interview.md 注册为离线网站章节；docs/learning-evolution.md 记录阶段目标、已交付与下一轮验收。按 agent.md 运行回归、构建、浏览器验收并重建检查离线官网。后续每日只完成一个可验证主题，进度从台账恢复；待办用尽后建议下一阶段，不无限堆功能。

## 实现与证据边界

静态课程本身不调用模型、MCP 或执行 shell。实验命令由用户在本地开发环境运行。既有 FTS5 不称为向量 RAG，裁剪不称为长期记忆，进程隔离不称为代码沙箱，固定独立复核不称为自主多 Agent。测试、真实 SDK 兼容和真实模型质量分开记录；不编造生产指标、用户贡献或私有思考链。

## 上下文与检索实验

新增 `agent:learn:context`，复用真实SDK与临时runtimeFixture，每场景独立数据库，模型预设直接回答，工具目录缩为一个只读schema且不实际调用。六场景分别对照ranked/diverse；同样14轮历史下recent、budgeted 8000字节、当前问题补回合成任务ID；以及必需当前输入超预算。拒绝场景也是符合预期的成功实验。

固定14轮历史加当前问题，共29条候选，避免把最近30条窗口与后续预算裁剪混为一谈。报告仅记录角色、轮次标记、合成ID可见布尔值、来源结构、字节计数和台账，不输出完整提示。HTTP请求体字节与contextBytes分别命名；固定fixture tokens不用于计费结论。检索对照报告文档与非重叠片段数，不把diverse当作必然提高准确率。

脚本不接受参数/真实模式，使用固定开发配置与显式Worker参数；启动监听前校验环境，结束清理本轮临时资源。固定白名单文件摘要在运行前后核对，报告包含时间与未验证边界。沿用已有OpenSpec格式，未安装新技能或执行其CLI。

## 授权与意图实验

新增 `agent:learn:intent`。三个独立临时场景都要求只查询billing，资源environment固定test，仅开放service_status，静态constraints.service为billing/inventory。真实SDK接收受控模型预设的billing、inventory、payroll参数；只改变目标，不改用户问题、权限和工具Schema。前两组应真实查询一次并返回给第二次模型请求；越权组应403且无工具步骤。

报告分别记录用户要求、模型提议、实际MCP查询、持久步骤与模型收到的工具结果目标。`scenarioMatched`表示行为符合实验预期，`intentMatched`仅表示合成字符串事后相等；后一值不参与工具放行。两者不可合并为笼统的“安全通过”。固定费用单价与DAILY_COST_LIMIT均为0，避免继承宿主计费配置破坏本地可复现性。

拟议前置绑定独立标为未实现：绑定对象应来自可信的本轮结构化选择/确认，限定资源、工具、规范化目标和轮次，在实际调用前与静态授权共同校验；缺失或含糊时澄清，不从模型提议反向生成被信任的绑定。本轮只记录其验收条件，不添加自然语言解析、API字段或DTS适配。

## 写入结果未知实验

新增 `agent:learn:unknown`，通过实际HTTP `/executions/tool` 创建固定写计划并调用审批/取消/核验接口；每组先观察awaiting_approval且无写入。四组分别为计划后资源变化、实际写入后代理丢弃回包、发现目录时取消、实际写入但回包屏障中取消。第二组继续只读对账，检查unknown→success而写计数不变；重复批准不得重发。

代理在每次实际write tools/call入口计数，fixture在应用内存变更后另计数，避免把远端幂等去重误当平台未重发。报告按检查点保存run与step、HTTP、读写计数、核验结果和槽位；平台unknown与测试观察器已知写入分开陈述。调用固定执行器应持久为direct/1，模型和tokens始终0，无需SDK预热。资源环境固定test，只开放目标billing的写入maintenance与对应只读核验，通知仅入本地台账且不连接外部渠道。

所有屏障有限等待，正常收尾释放等待并关闭本轮临时服务；强制终止不保证清理。不把fixture的isError回包称为丢回包，也不推导exactly-once。在途核验撤权复查已在全天循环5的执行回归中单独修复和验收；本四组教学实验不模拟该并发场景。

## 固定独立复核实验

新增 `agent:learn:review`，每场景独立临时数据库，真实AgentScope 2.0.8/prefork、test环境、本机模型和单一只读service_status。五组分别为正确billing证据+pass、无实时证据断言+block、相同缺证据问题/候选+错误pass、查询授权内inventory却问billing+block、已有证据但reviewer HTTP503。最后一组不重试，错误候选不发布；第三组发布是预设反例，不是保护成功或真实错误率测量。

脚本核对实际模型请求数、分析与复核阶段tokens、MCP调用、证据与step关联、返回与回读候选是否发布、持久review及trace状态。HTTP200/execution success与review blocked/unavailable和trace blocked/error分别记录。reviewer只有system/user两条消息且无工具；其输入包含问题、候选和本轮实际证据，不输出完整载荷到报告。

报告带固定白名单源码摘要与时间、scenarioMatched、realModelQualityAccepted=false。人工表保持pending、评分null、人员/时间/说明空白；建议按目标、证据、新鲜度/冲突、不确定性和故障解释评判。真实模型对照、人工打分及收益评测均未执行。费用与日限固定0，拒绝参数和真实模式，清理本轮临时资源；不承诺强制终止清理。

## 可观测性实验

新增agent:learn:trace，四组独立临时数据库、真实SDK/prefork和仅只读test工具。模型等待、工具等待分别注入160ms本地异步等待并记录观察器起止，与对应节点耗时核对下界，不按单机耗时比较真实性能。第三组工具isError应产生失败步骤、错误trace及一条模型请求；第四组工具成功返回合成degraded与旧reportedAt，执行/trace仍完成，证明流程状态不判定业务健康。

保存实际脱敏trace、台账状态、观察器计数/固定usage和来源摘要，不保存提示/候选/工具正文。工具时间和业务状态仅作为本地观察器标签，明确不来自trace；不把trace结束时间当作业务快照时间。真实费用为null；模型响应固定30tokens，仅核对计数。正常收尾清理本轮服务，强制中断未验收。OpenSpec技能查找无结果，沿用本目录格式、不执行CLI。
