# 设计与验收边界

## 报告与复核的关系

回放报告仍是不可覆盖的原始证据。新模板只引用其 SHA256 和候选摘要，并对每个案例记录执行阶段、输出摘要、复核状态、审核类型和证据引用。审核文件与原报告分开保存，避免修改已生成的自动证据或把事后意见伪装成运行时判断。模板和检查结果以权限 0600 排他新建，保留历史拒绝记录；修复后的报告须重新生成并独立复核。

检查时重新读取报告并计算摘要，校验版本、模式、案例唯一性、候选摘要、逐条输出绑定及阶段证据。前置拒绝须保持 403、失败执行、零上游调用/工具步骤和未越过边界；成功只读须保持 200、成功执行、精确一步只读工具调用和有效查询快照。不能只信任报告自带的自动通过布尔值。待审或缺项不得宣称已逐条审阅；拒绝项可标为审阅完成，但不得宣称复核通过。过期或篡改的报告/复核必须拒绝。输入无效与有效但未满足复核条件使用不同退出码，方便自动化门禁识别。

## 工程复核与人工声明

复核 schema v1 在每条记录加入可选 `reviewerKind`，枚举值为 `human`、`ai`、`unspecified`，缺省按 `unspecified` 处理。新模板显式给出 `unspecified`，审阅者据实填写类型、姓名或名称、时间、具体理由和证据引用。旧已完成记录仍可用于工程复核，但不会被当成人工记录。未审条目不计入 `counts.completedByReviewerKind`，批准与拒绝的已完成记录按类型计数。

检查项从 `human_review` 改为 `replay_review`。`reviewComplete` 表示没有待审；`reviewReady` 要求逐条批准、当前候选摘要一致且自动证据通过，可由 AI 工程复核满足。`humanReviewComplete` 仅在全部条目明确为 `human` 且批准时为 true；混合类型、未声明、待审或拒绝均为 false。CLI 同时输出工程复核与人工声明状态，不把 AI 结论伪装成人工审批。

## 受控答复与历史拒绝

原受控查询答复没有报告状态、上报时间、查询时间和新鲜度，审查应记录拒绝并保留原报告。夹具修正后从本轮成功工具消息的结构化结果读取 `state`、`reported_at`、`queried_at`、`freshness`，输出四个字段；不可使用预设状态、静态时间或旧快照凑齐答复。新报告中的答复应与本轮持久查询快照一致，再生成新的摘要绑定模板和审查记录。此流程修正合成夹具的覆盖，不代表验证真实模型质量或生产任务状态。

## 质量边界

模板不自动填写审阅结论，也不核验审核人身份或原始业务事件。即使每条结果均被 AI 或人工批准，结果仍明确 `productionAccepted=false`，因为合成重构回放不能替代真实用户来源核实和当前候选的真实模型发布评测。跨区域案例在模型前被拒绝，审查其拒绝说明和执行证据，不评价模型答复，也不能据此宣称历史模型换目标行为已回归通过。

## 验证

专项测试覆盖有效报告、待审、拒绝、漏项、重复、摘要过期、答复篡改及不可覆盖输出，并覆盖全部 AI、混合类型、明确人工与旧未声明记录的计数和状态。受控回放核对答复四字段来自实际工具结果；分别保存原报告拒绝结论和修正后新报告的逐条工程复核。共享代码运行 `npm test`、`npm run build`，文档运行 `npm run docs:build`、`npm run docs:check`；页面进展检查桌面和窄屏。
